# Route.it — Decision Register & Conflict Resolution Log

This register records all cross-document conflicts identified across `Route_it_Master_Document.md` (v2.0), `Route_it_Phase5_System_Architecture_final.md` (v0.2), and `Q-HGALS_5.md` (v5.0 Revised), together with confirmed decisions and documented, reversible defaults for open items (`U-1` through `U-15`).

## 1. Resolved Cross-Document Conflicts

| ID | Conflict Description | Earlier / Conflicting Statement | Controlling Authority & Resolution |
|---|---|---|---|
| **CR-01** | **Vehicle Activation Accounting Period** | Master Doc §5.3 & Q-HGALS 5.0 initial draft charged activation "once per active vehicle per planning run". | **Phase 5 v0.2 Addendum A & Q-HGALS 5.0 Rev §2, §4.4**: Activation is charged **once per vehicle per operating shift** (`shift_id`). `A_shift` (vehicles already posted in `shift_activation_ledger`) have incremental activation weight `w_k = 0`. Historical ledger rows are sunk and never reversed. |
| **CR-02** | **Anonymous Split Segments vs. Vehicle-Specific Ledger** | Split DP partitions a giant tour into anonymous segments, while `shift_activation_ledger` tracks specific `vehicle_id`s. | **Q-HGALS 5.0 Rev §2.1–2.6**: Under MVP homogeneous fleet assumptions, eligible vehicles `K` are sorted by `(w_k, 1[k ∉ A_shift], vehicle_id)`. Prefix sums `G_C(m)` and `G_N(m)` provide exact route-opening marginals during Split DP. Terminal assignment pairs sorted selected vehicle IDs with canonical route descriptors sorted by `(departure_second, stop_id_sequence)`. |
| **CR-03** | **Fleet Count Symbol (`M_active`) Ambiguity** | Earlier drafts used a single `M_active` symbol across initial plans and replans. | **Q-HGALS 5.0 Rev §2.3 & Phase 5 Addendum A.3**: Expose all three distinct counts: `M_routes_used = m`, `M_new_activated = G_N(m)`, and `M_shift_activated_after = |A_shift| + G_N(m)`. The comparator uses `M_shift_activated_after` as the normative fleet-count tie-breaker. |
| **CR-04** | **Balanced Profile Normalization** | Master Doc §5.9 uses `(C - C_best)/(C_worst - C_best)` min-max scaling; Q-HGALS 5.0 uses robust inter-decile scales `S_C = max(1, RoundEven(Q_0.90 - Q_0.10))` and `S_I = max(1, RoundEven(Q_0.90 - Q_0.10))` with independent anchors `C0, I0`. | **Q-HGALS 5.0 Rev §6.7 (`ALG-06`)**: Default to the Q-HGALS 5.0 exact rational cross-multiplied comparator `(C_dec - C0)*S_I + (I_idle - I0)*S_C` with Type-7 quantile calibration (`S_C, S_I >= 1`), while also supporting configurable `MIN_MAX` normalization mode via `profile_params` for backward traceability. |
| **CR-05** | **Driver Productivity Cap Reference (`C_min` vs. `C_ref`) & Hierarchy** | Master Doc §5.9 defines `C <= C_min + ΔC_max`; NP-hardness prevents guaranteeing global `C_min`. Earlier drafts also conflicted on whether coverage precedes cap. | **Q-HGALS 5.0 Rev §3.1–3.2 (`ALG-03`, `BP-05`)**: Hard feasibility → cost-cap eligibility (`C_dec <= C_cap = C_ref + ΔC_max`, inclusive) → lexicographic coverage `(N_C, N_S, N_F)` → `(I_idle, C_dec, M_shift_activated_after)` → deterministic signature. `C_ref` is obtained via a frozen Cost-focused reference pass in the same context and flagged with `c_ref_is_upper_bound = True`. |
| **CR-06** | **Evaluator Start State for Replanning** | Q-HGALS 5.0 initial §3.7 started every route at the depot at `t_k`. | **Phase 5 §11.2 (`E1`) & Q-HGALS 5.0 Rev §6.9**: Generalized `RouteStart(node_id, start_time_s, initial_load, locked_first_stop_id)`. Depot start is the special case where `node_id = depot`, `start_time_s = t_k`, `initial_load = sum(d_i)`. |
| **CR-07** | **Solomon Benchmark Time-Window Semantics** | Route.it constrains service completion (`D_i <= b_i`); Solomon VRPTW benchmarks constrain service start (`B_i <= b_i`). | **Phase 5 §3 (`C6`) & §15.4**: Route.it native evaluator strictly enforces `D_i <= b_i`. The `SolomonAdapter` translates Solomon due dates as `b_i_routeit = b_i_solomon + s_i` when running literature-equivalence benchmarks, explicitly recorded in `EvaluationContext`. |
| **CR-08** | **Acceptance Criteria Numbering (`AC-01..13` vs. `AC-01..12`)** | Phase 5 prompt merged capacity and hard windows into `AC-03`; Master Doc uses `AC-01` through `AC-13`. | **Phase 5 §3 (`C1`) & Q-HGALS 5.0 Rev §5 (`ENG-10`)**: Preserve Master Document `AC-01..AC-13` as primary IDs and cross-reference all 54 mathematical fixtures (`ACT`, `SPLIT`, `CMP`, `IDLE`, `PROF`, `QPSO`, `ROAD`, `MNY`, `EVAL`, `DYN`). |

## 2. Reversible Implementation Defaults for Open Items (`U-1` through `U-15`)

Where the specifications leave business policy parameters open for operator confirmation, the implementation enforces explicit configuration fields and uses the following documented, reversible defaults when not overridden by the user/API request:

| Open ID | Topic | Reversible Implementation Policy (Marked in Config & Context Hash) |
|---|---|---|
| **U-1 / ALG-06** | Balanced Normalization | Default `QUANTILE_TYPE7` (Q-HGALS 5.0 §6.7 exact cross-product `(C_dec - C0)*S_I + (I_idle - I0)*S_C`); selectable `MIN_MAX` in `PlanningConfig`. |
| **U-2 / BP-05** | Productivity Reference `C_ref` | Two-pass orchestrator runs deterministic constructors + local search in Cost-focused mode first to freeze `C_ref` (`c_ref_is_upper_bound = True`). Requires explicit `max_extra_cost_paise >= 0`. |
| **U-3 / BP-01** | Target Fleet Semantics | Configurable via `target_fleet_policy`: defaults to `ELIGIBLE_POOL_AT_MOST` (`m <= M_target`, empty routes never materialized, per Phase 5 §5 / Q-HGALS `BP-01`), with `EXACT_ACTIVE_COUNT` (`m == M_target`) available as an explicit policy option. |
| **U-4 / ALG-02** | Shift Accounting Period | Scoped to explicit `shift_id` (UUID) on `PlanningRequest`. Users can create a new shift or attach multiple planning/replanning runs to the same operational shift. |
| **U-5 / BP-03** | Departure Time Policy | `departure_set_utc_s` is an explicit finite tuple of integer UTC epoch seconds (e.g., single configured dispatch timestamp `(t_0,)` by default, or an explicit finite grid `(t_0, t_0+300, ...)`). |
| **U-6 / ALG-04** | Rounding Granularity | Versioned as `ROUND_POLICY_V1_ROUTE_ORDER_EVEN`: Round-half-to-even (`RoundEven`) once per route for distance (`d_k * r_d / 1000`), once per route for paid time (`tau_k * r_t / 3600`), once per served soft order for SLA (`L_i * p_i / 60`), and exact integer paise per newly activated vehicle. |
| **U-7 / BP-02** | Within-Tier & Profile Tie-Break | Versioned as `TIE_POLICY_V1_CANONICAL_SIGNATURE`: (1) Served-order bitmask in `(CRITICAL, STANDARD, FLEXIBLE)` ascending `order_id` order (inclusion preferred at first differing bit), (2) Canonical route signature sorted by `(vehicle_id, departure_s, tuple(stop_ids))`, (3) SHA-256 canonical plan hash ascending. |
| **U-8 / ENG-07** | Target Instance Size & Pilot Area | Supports arbitrary graph extracts and synthetic/urban networks (default Vadodara / urban pilot network fixture + Solomon 25/50/100 benchmarks). |
| **U-9 / ENG-01** | Turn Restrictions & Road Model | `ProfileGraphOracle` enforces directed edges, one-way rules, strongly connected component (SCC) reachability from depot, and Ichoua-Gendreau-Potvin link traversal (`FIFO` by construction); reports `road_model = "node_based_no_turn_restrictions"`. |
| **U-10 / ENG-08** | Mapbox & Geocoding Terms | Configurable via `.env`. Browser uses public token for temporary geocoding; backend stores dispatcher-confirmed coordinates and sets `address_source = DISPATCHER_TYPED` unless `MAPBOX_PERMANENT_GEOCODING_ENABLED=true` is explicitly configured. Includes offline local gazetteer/interactive map pin selection so the app works 100% offline without external keys. |
| **U-11 / D13** | Travel-Time Integer Rounding | `CEIL_SECONDS` (round up to whole seconds on interpolated profile lookups so arrival is never optimistic, preserving FIFO monotonicity). |
| **U-12 / ENG-06** | Frozen Benchmark List | 6 solver strategies under identical `ISolverStrategy` and `CanonicalEvaluator` budget: `CONSTRUCTIVE`, `SPLIT_BASELINE`, `LOCAL_SEARCH`, `ALNS`, `GA`, `QPSO` (`Q-HGALS 5.0`), plus `ORTOOLS_ADAPTER` (when `ortools` is installed, with capability matrix reporting). |
| **U-13 / BP-06** | Service Duration Source | Required integer `service_seconds >= 0` per order; validated by Gatekeeper. |
| **U-14 / D9** | MVP Road Oracle | `EuclideanOracle` (exact integer-scaled or metric Euclidean) and `ProfileGraphOracle` (in-memory time-dependent profile oracle over directed graphs). |
| **U-15 / Addendum A.2** | Activation Posting Trigger | Configurable `activation_post_trigger`: defaults to `PLAN_PUBLISH` (atomic transaction with plan publication, per Phase 5 Addendum A.2), with `VEHICLE_DEPARTURE` supported as an option. |
